# 交互的绘制模式

一份给「往视图里画东西的那一方」看的文档：一个应用的表面由什么构成、一次交互从人动手到画面上出现东西中间依次发生什么，以及哪些决定归应用、哪些归渲染器。它不是 accrete 的语法手册（那是 `external-integration.md`），也不描述某个具体应用——只描述形状。

全文的前提是一条分工：**渲染器没有业务逻辑。** 它执行操作，不解释动作。所以「我发出去的消息出现了」「提交表单后出现一行提示」这类事情，无法由客户端推断，也不能由客户端乐观插入：客户端不知道一条消息是一行、这一行该进哪个列表、长什么样子。**显示逻辑归应用，机制归渲染器。**

## 1. 基础视图，和它上面的一系列操作

这个库给应用的是**一份可以操作的基础视图**：先有一份视图——一块可以动手的场地——此后发生的一切都是在这份视图上的一系列操作（`create`、`set`、`append`、`remove`、`patch`）。这就是 Accrete 这个名字的原义：视图是累积出来的，不是每次变化都重建一遍。

基础视图怎么到客户端，与 accrete 无关：

- 走 socket 时最自然的是连接建立就推送——那里没有「请求」可言，连接本身就是起点。
- 传统应用完全可以把它放进一个文件，用户请求首页时把这份基础视图发过去。
- 也丝毫不要求 socket：基础视图里放一个链接，点它请求**另一个**视图、替换当前这个。替换是操作，不是新机制。

同样与视图无关的是**谁产出这些操作**——一个进程、几个控制器、几个服务；它们分布在哪儿，都不是视图的一部分。视图只认操作的形状，不认产出它的组织形状。

上面这些都不影响下面三条不变量：

- **一个槽位名是基础视图的作者写下的一句话**（「我的表面在这里读」），所以只有他能说这句话是否成立——这正是名字必须由供应基础视图的一方声明、而绝不由往里画的执行器去猜的原因。
- **操作不修改基础视图**：操作寻址的是它声明过的槽位和行，一个它没写过的名字是错误，而不是一个新的槽位。
- **行的身份在数据里**（`data.id`），所以操作对「它点名的行」幂等，而不是对「可能已经挪动了的位置」幂等。

## 2. 一次交互的五步

下面这个顺序就是对话里一条消息的顺序，它只是这个形状的一个例子：

1. **客户端发事件。** 载荷带人做了什么（文字），如果这一方要画面，还带要画进哪些槽（`rack` = 行列表，`text` = 区域）。客户端不画。
2. **应用先把这件事变成事实。** 落盘，而这次写入就是这次交互的 id 被铸出来的地方。没有这一步，后面说的都没有依据。
3. **应用先说话，再干活。** 先发一个回执（`{turn}`——它让客户端能把自己发的那句话和后面的答案对上号），然后**一批**操作：把用户这一行 append 进 `rack`、建好答案要流进去的区域、append 读这个区域的气泡。批内顺序是语义：填充区域的 patch 必须在建它的 `set` 之后。
4. **这时才开始干活。** 答案的每一段只 `patch` 第 3 步建好的区域，不重画舞台。
5. **结束要说出来。** `done`，或带原因的 `error`。失败不撤销第 3 步：用户那句话留在屏上是事实。

按钮、表单同理：点一下，客户端发事件，应用回答以操作（可能只是 append 一行提示）。没有哪一步是客户端能自己完成的。

## 3. 容器形状归应用

同一批行在一个 `rack` 里，彼此的区别是行自己的容器：对话流里用户行靠末端对齐并带强调色，回复行铺满、无强调色。这个差别**是帧携带的类名**，不是渲染器的知识——一个从没听说过「对话」的渲染器照样把两者画对。

行身份在数据里（`data.id`），复用的版式在 `rack.item`（ADR 0020），摆法在 `attrs.view`（ADR 0024）。应用决定行是什么、装什么；渲染器决定这些行怎么摆、怎么进出场。

## 4. 帧里没有的东西

- **停多久、要不要淡入淡出、跟不跟尾巴。** 那些是渲染器的词汇（ADR 0024），应用只送行；
- **「通知」「横幅」「聊天气泡」这类类型名。** 它们是值的组合，不是类型（ADR 0024 §8）；
- **本地乐观插入。** 见开头：客户端不知道这条该画成什么。

所以「用户发了消息，他自己看得见吗」的答案是：看得见，因为应用在他发出的那一刻送了那一行；不是因为客户端猜的。

## 5. 这条模式对应用的要求

1. 事实先落，画面后发——否则画面说的东西没有依据；
2. 画面在**干活之前**发——否则一次慢调用就表现为「发了没反应」，一次失败就表现为「发了却像没发」；
3. 每一帧带同一个归属 id（如这一轮的 `turn`），让客户端把同一次交互的后续都挂回那一行；
4. 只送人需要读的（见 gravity ADR-0010：工具调用的参数与结果留日志，界面上至多发标题和状态）。
