# ADR 0028: One click can raise two events — one local, one remote

状态：已接受
日期：2026-11-18
仓库：fluxen

## 背景

导航是一个 `select`：选项是各岛的名字，点击写本地值槽 `page`，`tiles` 订阅同一个槽
切页。整个过程不出网——快，也不用等任何人。

但 venue 因此不知道人走到了哪个岛。而"只叫正在看的那个岛"（惰性 connect）需要一个
触发源：没有它，惰性就没有入口，只能退化成"所有岛都叫"或者"页面加载时的那个岛"。

两条路摆在这里：

```
A  全部保留本地切换，取消惰性     删 island uplink + LastIsland + 单岛 connect
B  保留惰性，点击时上报一次      本地切换之外多发一条，venue 记下并叫那个 booth
```

选 B。理由不是省流量，是**"上次在哪个岛"必须由 venue 记住**：纯本地切换天然跨不了
设备，而这是同一个人在两台机器上的同一件事。而惰性本身省掉 N-1 个 booth 的 connect
与绘制，不是小事。

## 决定

`Sink` 加一个可选字段：

```json
{"dest": "page", "scope": "local", "report": "island"}
```

这个出口于是说：**这次点击产生两个事件**——一个落进本地槽（页面立刻切换），一个
发往 venue（`report` 给的事件名）。两个事件由同一次交互产生，谁先谁后不需要约定；
它们的载荷都是这次点击的值，落点各自处置：本地槽按 ADR 0010 包成 `Outflow` 落槽，
远程那头把值当作事件的 `data`。

事件名由帧给——框架不认识"岛"这个词，只认识"这次交互还该告诉谁"。

**它在 `local` 上，不在新节点或新 `kind` 上。** 本地与远程是同一次点击的两个去向，
属于同一条绑定；再加一个 `kind` 会让人以为两者可以分开选择，而实际上远程事件只有
在"本地已经变了"之后才有意义。

于是声明空间有三态，一帧可以任选其一：

    只写 local              点击只改本地值，不出网（切页的常态）
    写 local + report       点击既改本地值，也发一条远程事件（首次走进某岛）
    写 dest                 点击只发远程事件，本地不动（既有形态，ADR 0023）

`report` 是可选的：没有它，行为与从前一字不差——这是同一个绑定的两种密度，
不是两个功能。

## 后果

- 帧可以声明"本地切换 + 上报"，venue 侧不需要新的下行通道。
- prism 的 `island` 上行处理器接受两种载荷：裸值（渲染器）与 `{booth: ...}`（程序）。
- 惰性 connect 有了触发源，ADR-0019 那句"切换不出网"改成"首次访问某岛出一次网，
  之后不出"。
