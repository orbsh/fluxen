# 0047 — 一张 hooks 表，四个口子

状态：Accepted（实现完成，单测待补）

## 问题

宿主对渲染器的需要，除了"把设置当数据传进来"（ADR 0045）之外，还有四种：连接开/关要知道、整页重铺要知道、某个槽的值要观察、上行的载荷要改写。四种都在同一个生命周期里，散成四个 mount 参数会让"这个页面和渲染器之间发生了什么"没有一处可以通读；而且其中的上行改写必须与下行观察用同一套入口，否则宿主得记两套地址。

## 决定

```js
await mount(el, {
  codec, path, query,
  hooks: {
    open:   (send) => send("identify", { token }),        // 每次 socket 打开（含重连）
    close:  () => {},
    create: (root) => {},                                  // 根被替换：整页重铺
    slots:  { "ui:token": (value) => {}, "*": (value) => {} },
    dests:  { "*": (dest, data) => data },
  },
});
```

### 判据：按 action，不按"有没有 slot 字段"

`create` 带的是 `slot: ""`——那是**根**，不是缺失。用"有没有 slot"当判据会让根槽成为灰区，也会漏掉将来打到根的 `set`。所以：`create` 一个口子，其余 action 按它们**写到的那个槽**进 `slots` 表（`remove` 也算，值为空）。

### 实现形状（写代码时定下来的，不是最初的设想）

- **`Ctx` 里不放 JS 函数**。`Ctx` 被 view 闭包捕获，所以必须是 `Send + Sync`，而 `js_sys::Function`
  两者都不是；`SendWrapper` 只给 `Send`，进 `Arc` 仍不过。解法不是通道——wasm 单线程，调函数就是
  在 JS 侧执行——而是：**函数住 `thread_local!` 表里，`Ctx` 只拿 id**。适配器闭包捕获一个 `u32`，
  天然 `Send + Sync`。
- **`open` 的实参是页面的上行句柄**（`window.fluxen.send`，boot 挂载时发布、socket 打开时必定已在）。
  `open(send)` 的 `send` 就是它，没有第二个来源。
- **`slots` 的合并是一条地图，不是队列**：`set` 只覆盖 `pending[名称]`，`drain` 在消费帧的那个
  Effect 每个 batch 的末尾跑一次。这样不需要调度器（`spawn_local` 在此 crate 不可用：它同时为服务
  端编译），也不会让宿主回调待在触发它的那次写里面。
- **`create` 在 layout 被替换处通报**，`open`/`close` 由 `LiveWs::on_lifecycle` 通报：`open` 排在
  outbox flush **之后**（保证宿主的第一句话是这条连接的第一帧），`close` 排在未发帧丢弃**之后**。

### 五条语义

1. **`open` 每次连接都跑**（首连与每次重连）。transport 在 open 之前 `emit` 的帧是排队的、open 时按序 flush（`transport-ws/src/live.rs:20`、`:117`），所以 `open` 里说的第一句话不会漏，而且排在所有排队的上行之前。
2. **`close` 时未发出的帧丢弃并记日志**，不带到下一次会话——上一段会话里"点了个按钮"的动作被重发到新会话，是一次没人认领的重复提交。
3. **`create` 每次根替换都触发**，包括重连后的重铺；它不产生"所有槽变空"的合成通知。重铺页面不是"这些槽被写成空"，尤其不该让宿主擦掉自己存的东西。
4. **`slots` 在值落地之后通知**，微任务里跑、同一微任务内同名槽合并（只留最新值）、每个回调的异常各自捕获并记日志（一个订阅者出错不能变成白屏）。订阅建立时**补发该槽的当前值**：服务端可能在挂载之前就发了（`ui:token` 就是这样），只订阅未来的 `set` 会永远收不到。
5. **`dests` 在编码之前同步运行**，按注册顺序、具名优先于 `*`；返回值替换 `data`；抛错则丢弃这一帧并记日志（绝不发半成品）。它阻塞的只是这一帧，不在渲染路径上。

## 为什么不是"每条上行都盖一个 token"

凭证是**连接级**事实，不是消息级。持久连接上发一次就够；要重说的场合只有一个——新的 socket（重连），而那正是 `open`。按消息盖章会让每条帧带上同样的字节，也会让读者以为这是个无状态请求。

## 代价

- 渲染器多了一个 API 面（四个回调 + 调用时序 + 异常隔离 + 退订）。这些语义不写死就会各自漂移，所以它们在上面的五条里，而不是在注释里。
- 宿主必须自己决定"我的会话放哪"（存储、地址、还是服务端签发）。这正是 ADR-0046 的延续：渲染器提供口子，宿主提供意见。
