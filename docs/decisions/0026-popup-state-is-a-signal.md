# ADR 0026: A popup's state is a signal, not `:hover`

状态：已接受
日期：2026-11-18
仓库：fluxen

## 背景

`popup` 的显隐一直是 CSS：

```css
.popup > .body { display: none; }
.popup:hover > .body { display: flex; }
```

`:hover` 是一条只有指针设备才有的状态。触屏没有它，触屏上 `popup` 根本打不开——
而"点一下弹出来"恰恰是触屏最需要的交互。同一段 CSS 还让状态藏在样式层：帧重建、
节点被移走再放回，`show` 没有任何地方可以表达，也没有任何地方可以读。

## 决定

1. 显隐由本地信号 `show` 驱动：`trigger`（`sub[0]`）点击切换，`Esc` 与点击外部关闭，
   `.open` 类是唯一开关。
2. 三个容器的分工按"这一层占不占布局"和"谁决定它出现"分：

   | 容器 | 占布局 | 谁决定出现 |
   |---|---|---|
   | `fold` | 是（inline 展开，撑开） | 自己的信号 |
   | `popup` | 否（覆盖在触发器旁） | 自己的信号 |
   | `layer` | 否（全屏遮罩） | 所绑槽是否非空 |

   所以 `popup` 不并进 `fold`（会挤走下面的内容），也不并进 `layer`（那是模态，
   不是贴着触发器的浮层）。三者都该由信号驱动——没有一个该靠 CSS 状态。
3. `sub` 不足两个就什么都不画：少写一个子节点是帧的错误，不是"可以渲染半个弹窗"。

## 后果

- 触屏可用（点击而不是悬停）。
- 状态在信号里：可以在它上面接"打开时加载""关闭时清空"，不需要读计算样式。
- 关闭腿挂在 `window` 上（覆盖层的点击可能落在任何地方），句柄随组件作用域销毁。

## 未决

- 定位方向仍由宿主容器决定（`position:relative` + `top:100%`）。触发器的浮层要
  贴右/贴上时需要 `attrs` 表达方向——现在 `DirectionAttr` 是 flex-direction 的，
  不是浮层位置，加字段是另一条决策。
