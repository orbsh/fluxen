# 0048 — `oklch` 色盘是一个字段，不是第四种控件类别

状态：Accepted（已实现）

## 问题

表单里"挑一个颜色"这件事，`input` 与 `select` 都不合适：`input` 是键盘进、字符串出，让人手写 `oklch` 三元组
既容易写错也不像在挑颜色；`select` 是一列可选项，而颜色是一个**二维的连续面**。

这一条最初出现在 reflux 的设置页（核心的样式令牌要能被调），但问题不在那一个页面：任何宿主都要让使用者挑
颜色。渲染器如果只会"打字"和"列表"，每个宿主就要自己搭一个（页面里塞 canvas、自己算坐标、自己把结果塞回
某个槽），而这些事彼此一模一样。

## 决定

`accrete` 里加一个节点 `disc`，与 `input`、`select` 同层：**一个字段**，一个值，一种时机。它的**手势**是
`oklch` 平面上的一个盘——盘面正好有两个自由度：

- **角度 = 色相**（0 在正上方，顺时针，`0..360`；与 `conic-gradient` 的扫描方向一致）；
- **半径 = 彩度**（圆心是 0，边缘是 0.4，也就是颜色成员校验的那个上限）；
- **亮度**盘面放不下（那是第三根轴），由 `attrs.light` 钉住，盘就画在那个亮度上——所以它是空间的一片切片，
  不是整个空间。

```json
{"type": "disc", "tag": "accent", "attrs": {"light": 0.7}, "source": {"default": "0.7 0.12 200"}}
```

- **它的值是 `"<light> <chroma> <hue>"`**：写出来的 `L C H` 三元组，和颜色成员本来就是同一种拼法。于是成员
  值、校验器、宿主那一侧的 `oklch()` 合成都不必知道有个盘参与过；盘换掉，值不变。
- **它是一个字段，不是一种新东西**：`tag` 让它成为所在 `loom` 的一份（ADR 0032），出口与时机仍归 `loom`；
  它自己不发上行。点击是一次离散动作，所以它给 `Emit::IMMEDIATE`，不等邻居的 `change` 窗口。
- **颜色不算在渲染器里**：盘面是 `conic-gradient` 铺的 `oklch()` 停靠点，上面压一层从灰到透明的
  `radial-gradient`，混色由浏览器做——与 `select` 把选项渲染成节点而不是算一个菜单同一个理由。渲染器只做两件
  事：把点换成（色相，彩度），把三者拼成三元组。
- **中性颜色也在同一个盘上**：圆心就是彩度 0。所以"灰"不是一个要另配控件的情形，而是盘上的一点——宿主不必
  为中性令牌换一种控件。

## 代价

- **亮度改不了**：盘只给两项，第三项是页面钉的常量。要改就是页面的意见（给这个令牌换一个 `light`、或再加一根
  轴），渲染器不预设。这是一次取舍：盘面上多一根轴要另一种手势（拖动、双环），而字段的值只有一个。
- **只认点击，不认拖动**：一次点击是一个离散值，拖动是一串，需要先回答"什么时候发"。`select` 也只有点击。
- 盘面是**近似**：`conic-gradient` 的停靠点每 30° 一个，浏览器线性混色。够用来挑颜色，不是色彩学上的精确剖面。

## 顺带记下的一处渲染器事实

`select` 的选项行由它的 `source` 那个槽给，不是 `options`：`select.rs` 调的是
`use_source_list(&ctx, &accrete)`，而 `get_source` 回答的是值通道。摆进 `options` 的列表被忽略，控件画成空。
reflux 的 fixture 早已这么写（`tests/types_fixture.py` 的 `select` 注释）；把 `select.rs` 改成读 `options`
是另一件事，改的那天两处注释放下。
