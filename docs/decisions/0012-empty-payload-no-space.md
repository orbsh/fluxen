# ADR 0012: 空载荷的模块宿主不占位——尺寸随载荷生效

状态：已接受（2026-10-10 用户确认后实施）
日期：2026-10-10
仓库：fluxen

## 背景

ADR 0007 给 Canvas 的尺寸语义是"尺寸归 attrs"：宿主渲染节点时就把
`SizeAttr` 的 `height/width` 写进容器内联样式，模块随后按容器尺寸建 canvas。
Chart 同构，尺寸走 class（ADR 0009）。两者共用 `mount_module`。

这条语义在"一个 box 里图文混排、内容流式到达"的形态下露出一个后果：行是在
append 那一刻定型的，于是**模型还没到，它那块地已经被占了**。当时的
product_intro 演示（2026-10-10 并入 `examples/walkthrough.py`）里表现为一个 box
打开后，两段文字之间各自挂着一块 640×420 / 720×460 的
空白（用户 2026-10-10：「box 固定了大小，我希望是动态的撑开」，选定"模型区
一开始不占位、载荷到了才撑开"）。文字本身是动态的——流式打字时 bubble 一直
在长——定死的只有带尺寸的模块宿主。

ADR 0007 其实已经定义过这条语义的另一半：宿主的现有判据是"空槽/无载荷 =
`{}`，空 map 是合法『尚无数据』"。本 ADR 把"尚无数据"从**载荷语义**延伸到
**占位语义**，不新造概念。

## 决策

**空的 data 区 = 不占位。** 走 `mount_module` 的模块宿主在载荷为空时不占据
任何空间；载荷第一次变为非空时按节点尺寸撑开。

1. **判据（"空"是什么）**：宿主为缺失/空槽合成的那个值——`Null` 或空 map
   （`Value::Object` 且条目数为 0）。非空即"有数据"。节点的 inline default
   非空时行为与今天逐字一致，**wire 形状零变化**（不加字段、不改 serde）。
2. **不占位的形式**：容器内联样式置 `display: none`；有数据时写回
   `SizeAttr::size_style()`。不借用 `hide` 类——`.f` 与 `.hide` 同 div 实测
   互相压制（Pitfalls 已记），内联样式无此歧义。Chart 没有 SizeAttr，但隐藏
   同样生效：**规则不按"尺寸从哪来"分叉**，canvas 与 chart 一条判据。
3. **反应式，不重挂**：可见性与尺寸是**容器属性**的响应式绑定，不是布局平面
   的写入（布局平面写入会重渲整行、重挂行内每个模块宿主，§13 已实测）。模块
   的挂载路径——NodeRef on_load → import → 契约检查 → mount，以及三态
   `data-module-mounted` 护栏——一字不动。载荷到达时容器从隐藏转为可见、尺寸
   就位，模块自己的 ResizeObserver → `resize()` 接手重画：import 不重跑、
   GL 上下文不丢、已加载的资产不重下。
4. **载荷反应性**：现有 payload 闭包是挂载时读一次（`get_untracked()`），需要
   增加一个**受订阅的布尔派生**（空/非空）来驱动容器属性；这是本 ADR 唯一的
   新机制，仍然零新词汇。

## 明确不做的替代方案

- **"首次非空载荷才 mount"**：同样达到"不占位"，但要把载荷订阅提到 on_load
  的异步块之外并让它驱动挂载，等于重构三态护栏（ADR 0007 实现期踩坑最多的
  那一段）。而 resize 是模块契约里现成的一条腿，收益为零、风险不对等。
- **给 attrs 加 `grow`/`defer` 开关**：现有词汇已经足够（空即无），加开关
  等于把同一语义表达两遍——与"封闭词汇表"的取向相反。
- **靠示例写法绕过（先 append 文字、载荷到了再 append 模型行）**：那就是退回
  四个 box，正是本 ADR 要解决的问题。

## 后果

- 该演示（现 `examples/walkthrough.py`，一个 box 里还接了图表、摘要与复核表）：
  box 打开时只有第一段文字的位置；鞋载荷到达 → box 长出 640×420 → 第二段文字 →
  泼溅载荷到达 → 再长 720×460。即"载荷到了才撑开"。
- `examples/yaml/13.canvas.3dbrowser.yaml` 免费获得同一行为：两个 canvas 行
  绑槽、载荷在同文件后续帧 set，现在从挂载起不占位，载荷到达才展开。
- `00.radar.yaml`（chart 绑槽 `trend`）：图表宿主同样从空到有——行出现时图表
  那块先不占位，`trend` 的 set 到达才撑开。这是判据在 Chart 上的直接推论，
  不是特例；若将来要"图表先占位"，那是重新划判据，另立决定。
- **退化尺寸下挂载**（唯一的风险点，已实测无碍）：模块在容器隐藏时挂载，
  那时 client 尺寸为 0。3dbrowser 的 `resize` 齐备（canvas 1×1 → 640×420）；
  splatviewer 的 `resize()` 虽是 no-op，但 GS3D 自己观察容器，实测 canvas
  0×0 → 720×460。两个模块都能靠 resize 从退化尺寸恢复，不需要模块侧修复。
- 想要"固定尺寸的空盒子"的生产者，做法是发一个非空载荷（例如
  `{"assets": {}}`：map 有条目即非空），而不是加开关。
- 文档漂移（一并记下，不改历史 ADR）：ADR 0007 决策 1 里 `Canvas.attrs` 仍写
  着 `Option<ClassAttr>`，实现早已换成 `SizeAttr`（带 height/width）——0007
  未随实现更新。
