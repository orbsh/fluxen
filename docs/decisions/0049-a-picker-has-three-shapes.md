# 0049 — `picker` 的三种形状：折起来、朝哪个方向、能不能多选

状态：Accepted（已实现）

## 问题

`picker` 一开始只有一种形状：所有选项行摊在页面上，选中的那行变平（不可再点），其余可点。这在选项少、且
页面有地方时是对的——它把"有哪些选择"直接摆在眼前。但两个情形它撑不住：

- 选项多（五个以上）时，摊开的一摞会把版面压长，而使用者九成时候只关心"现在是什么"；
- 有时选项想要的是一排按钮（横向的开关组），而不是一列；
- 有时一个问题允许勾多个（标签、多值过滤）。

三条都是同一件事的参数，不是新的语义：还是"从一组里挑"，还是把结果交给所在 `loom` 的出口。

## 决定

`picker` 的三个属性（都在 `attrs` 里，都可缺省，缺省 = 现在的行为）：

| 属性 | 缺省 | 含义 |
|---|---|---|
| `expand` | `false` | `true`：选项折起来，页面上只站当前选择，点一下开浮层再挑；挑完（单选）自动收起 |
| `dir` | `col` | 选项的朝向：`row` 是一排按钮，`col` 是一列（浮层也按它排版） |
| `multiple` | `false` | `true`：可以同时挑几个；此时字段打包的是**键的列表**，单选仍是一个键 |

三条推论：

- **开合状态不上线**。它是手势，不是值：`open` 是渲染器自己的一份 `RwSignal`，和 `input` 的草稿值同一个性质。
  协议里没有"菜单开着"这种东西，服务端也不该知道。
- **多选只改值的形状**。单选 `pack` 成一个键（字符串），多选 `pack` 成键的列表；读回来时两种都认
  （`keys_of`）。于是同一个 `tag` 在两种形状下都是"一个值"，出口不必分情况。
- **浮层是本地图层**：一个铺满视口的透明层接外面的点击（关掉），`Escape` 也关（容器上的 `keydown`）。没有焦点
  陷阱，也不抢焦点——这一版只做点击，方向键留给以后。
- **浮层在两种皮肤下都是同一个盒子**：普通模式是面 + 1px 边 + 柔和投影（`is-border` / `is-shadow`），手绘模式
  由笔描边、笔再补一层"影子"，直边被样式表撤掉（`[data-rough="ready"]` 那条）。定位挂在外面一层包装上——皮肤
  给 `.is-border` 加了 `position: relative`，绝对定位的菜单不能被它拉回文档流。

## 代价

- 浮层只用绝对定位 + `z-index: 30`，没有"越出视口就翻到上面"的测量。够用，不是完备的定位器。
- 多选的值是列表，宿主侧的成员若只接受标量，就别开 `multiple`——这是宿主的取舍，渲染器不管。
- 摊开时的行多了一层 `display: contents` 的包装（挂响应式行用），它对布局是透明的；写 CSS 的人不会看见它。
- 键盘只有 `Escape`。方向键、Home/End、输入过滤都没做。

## 顺带

`picker` 的选项行来自 `source` 那个槽，不是 `options`（`use_source_list` 拿的是值通道）。这是既有行为，ADR 0048
里已经记过；本轮没有改它，只是在 ADR 0049 的用法说明里沿用。
