# 0055 — 颜色只住在 token 层：六个调色板名字，其余全是派生

状态：Accepted（2026-11-26 实现，测试守着）

## 问题

一份样式表里，颜色可以从三个地方来：调色板的 token、从 token 派生出来的值、以及某条规则自己写下的字面量。
第三种最省事，也最贵——它不是"多了一个颜色"，是**一个颜色的第二个来源**：主题一改，它不跟着改；暗色模式下它
还是那个浅灰；换一版皮肤，它是唯一没被换掉的东西。

审计时的实际分布：

- `var(--secondary)` 在规则里出现 12 次，其中 10 次是在画线（边框、描边、分隔）。"次色"这个角色其实在做两件
  事：调色板里的一个角色，和"界面上所有的线"。而 `--border-color` 早就存在，只有 2 处在用。
- 模块（图表）从 JS 写行内样式，`rgba(0,0,0,.18)` 这样的字面量出现 6 次：色块内环、菜单阴影、选中态底色。
- `--surface` 是两个写死的亮度（0.965 / 0.205），`--shadow-color` 是裸黑，玻璃效果里 4 个 `oklch(1 0 0 / …)`。
- `--border-style` 只被 `--border` 用一次，值永远是 `solid`。

## 决定

1. **源头只有两类值**：六个调色板名字（`accent` / `primary` / `secondary` 说"是什么"，`disabled` / `warn` /
   `error` 说"什么意思"）与两个模式端点（`--fg` / `--bg`，`light-dark()` 切换）。除此之外，没有第三种"基础色"。
2. **其余在 token 层算一次**：`--surface`（页面往墨的方向走一档，用 `color-mix` 写成混合而不是两个亮度，换纸
   换墨时它跟着走，两个模式下方向一致）、`--border-color`（= 次色）、`--wash`（悬停/选中底，墨 12%）、
   `--ring`（1px 内环，墨 18%）、`--shadow-ink`（墨 10%）。**alpha 而不是第二个灰**：洗色落在它下面的东西上
   （页面、卡片、面板），不自己挖一个颜色的洞。
3. **两个绝对量不派生**：`--ink`（黑）与 `--gloss`（白）。影子是没有光、玻璃的高光是有光，与主题无关；把它们
   从调色板派生，就是暗色模式下每张卡都发白光的原因。
4. **规则里只读 token，不写字面量**：`rgb()` / `rgba()` / `hsl()` / 十六进制 / 不带 `from` 或 `var()` 的 `oklch()`
   都算字面量。`crates/ui-assets/tests/tokens.rs` 把这条变成测试：切掉 `@layer tokens` 之后逐字扫描两份样式表，
   命中即红。
5. **模块不是例外**：图表模块从 JS 写样式，但它的颜色也读 `var(--ring)` / `var(--wash)` / `--surface`——一张自己
   注入的 `<style>`，内容是四个类规则。测试同时守它。
6. **内容色是唯一许可的例外，且写在测试里**：`--bar` 的三条渐变（L 黑到白、C 的彩度、H 的整圈色轮）画的是色彩
   空间本身，不是界面色。测试按声明名（`--bar`）放行，不按人记。

## 后果

- 12 处 `var(--secondary)` 各自归位：画线的 → `--border-color`，当底色的 → `--wash`。
- `--border-style` **留着**：在这份表里它只有一个读者（`--border`）、没有写者，看上去是死的，其实写它的是宿主——
  设置页的 picker 把它从 `solid` 切到 `dashed`，`--border` 跟着变（`gate_settings` 第 8 步量的就是这一条）。
- 选中/悬停的对比度略微变成 alpha：落在卡片和落在页面上不再一样深，这是想要的（之前是一个灰，两种底色上浓淡
  不同）。
- 暗色模式下 `--surface` 现在由混合算出（0.208 而不是写死的 0.205），差值肉眼不可见，但它从此跟着 `--bg` 走。
- 新增一条规矩给后来的人：**要一个新颜色，先问它是"调色板里的角色"还是"某个值的派生"**；两者都不是，说明它是内容。
- 测试是逐字扫描，不是解析器：`#face` 这样的 id 选择器会被当成颜色。目前两份表里没有，出现时把规则写清楚，
  不要放宽测试。
