# 0050 — 三种值类型，两种字段节点：一个行为的形式，与几种组件的一个名字

状态：Accepted（类型层已实现，2026-11-26；`picker` 的滑块与开关尚未画出——见「还没做」）

## 问题

表单里能拿到一个值的地方只有两处：`input` 和 `picker`（改名前的 `select`）。两处各只认一种值：

- `input` 的 `kind` 是六个裸词（`text` / `number` / `bool` / `password` / `button` / `submit`），形式齐全，但数字
  只是把 `type="number"` 交给浏览器：原生 spinner 的加减按钮在多数系统上只有 12px 高，按不到，页面上等于没有
  加减。
- `picker` 没有 `kind`：它永远是选项行，一行一个。数字、布尔借道 `picker` 时只能假装成字符串。

于是「调一个数字」和「开关一个布尔」在页面里有两副面孔，挑哪副靠页面自己拍；而「我要这个数在什么范围里」这句话
哪里都写不下。

## 决定

### 一、两种节点，两种减词法

这两个节点长得像，实际是两种完全不同的取舍，这一条是本 ADR 的主干：

| | `input` | `picker` |
|---|---|---|
| 是什么 | **一个行为**（往格子里填一个值）的六种形式 | **三种不同的组件**（菜单、滑块、开关）共用一个名字 |
| 省的是什么 | 记忆：学会一个行为，六种外形 | 词表：学会一个名字，三种组件 |
| 代价 | 形式之间的差异只能靠外观与解析表达 | 每种组件自己的参数都得塞进 `kind` |
| 判据 | 差别是「同一行为的另一种外形」 | 差别是「另一个组件」 |

于是两个节点都叫 `kind` 的字段，类型不同、回答的问题不同：`input` 的 `kind` 只回答「用哪种外形」，`picker` 的
`kind` 连**域**一起回答——滑块要知道区间，菜单要知道词表，开关什么都不需要。

### 二、`input` 的 kind 是形式（`InputKind`）

六个裸词，一个不少，与这条 ADR 之前逐字一致：`bool` / `number` / `text` / `password` / `button` / `submit`。
里面没有 `min` / `max` / `step`——**区间不是一种形式**，它是「按格拖动」这个组件才有的东西，属于 `picker`。

只有一处行为改了，与形式无关：数字框空着（或写了解析不出的东西）打包 **`null`**，不再是 `0`。「没写」和「写成
了 0」对人来说是两件事，而 `0` 是一个值。宿主按「空值 = 不设」接（ADR 0001 §3–4），所以字段第一次被画出来时
不会替人做主。

数字框还要多一条：**框里显示的是人的草稿，不是解析结果的拼写**。上一版把信号直接绑在元素的 `value` 上，于是
每敲一个字都把解析值写回去：敲 `1`，框里回写成 `1.0`，光标落在末尾，再敲 `8` 得到 `1.08`。文本扛得住这个往返，
数字扛不住。现在草稿是一份本地的 `RwSignal`，只在解析值与草稿对不上时才被外部写入替换（重置、别的写者），
所以光标不动，`18` 就是 `18`。

### 三、`picker` 的 kind 是组件（`PickerKind`）

```rust
pub enum PickerKind {
    Bare(PickerBare),        // Text（菜单）| Bool（开关）
    Stated(PickerStated),    // Number { min, max, step? } | Text { candidates }
}
```

wire 上保留这个不对称，因为它承载信息：declares-nothing 的就是一个词，declares-something 的才是 map。

```yaml
kind: bool                                       # 开关
kind: text                                       # 菜单，选项行来自 options 槽
kind: {type: number, min: 0, max: 64, step: 1}   # 滑块，按格走
kind: {type: text, candidates: [solid, dashed]}  # 菜单，词表写死在帧里
```

- **`kind` 缺席 = 菜单**。加了这个字段不移动任何旧帧：ADR 0049 的三种形状（`expand` / `dir` / `multiple`）原样
  生效，它们说的是菜单怎么摆，不是它是谁。
- **`min` / `max` 不是 `Option`**。滑块必须交代它接受哪些数——上一版把界写在宿主的校验表里，于是页面上的字段不
  知道界、浏览器帮不上忙，99.5 能进网络、能被存进状态，只在最后一步被丢掉。现在写不出「没有区间的滑块」。
- **`step` 是 `Option`**：`None` 是连续（元素上写 `step="any"`，可以平滑拖），`Some(n)` 是按格走。HTML 拒绝
  `step="0"`，所以声明成 `0` 的读回 `None`，而不是留给浏览器一个不起作用的属性。
- **`Bool` 没有分支**：「不需要参数」体现为没有字段，而不是一个全空的 struct。
- 菜单的封闭词表（`candidates`）是死声明、跟帧走；`options` 槽仍然给「从数据来」的选项行（ADR 0049 §顺带）。
  两者共用同一个形状，但不合并两个来源。

### 四、命名：`select` → `picker`

`select` 这个名字在本仓里搜不出来：`selector` 有 224 处、分布在 52 个文件（字段的落点属性、探针选择器、CSS），
而这个节点名只有 8 处。搜 `select` 等于搜 `selector`，改名不是为了好听，是为了让搜索可用。

选 `picker` 而不是 `control`：三个组件都成立「挑一个值」——滑块挑数、开关挑真假、菜单挑一个词，名字不偏袒其中
任何一个；而 `control` 是这两者的**属名**（本 ADR 标题里那个「两种字段节点」），拿属名命名一个种，读起来分不清
说的是哪一个。

改名一次到底，不留别名：`Select` / `SelectAttr` / `Accrete::select` / CSS 类 `.select` / wire `type: select` 全部
换掉。旧帧 `type: select` 现在**解码失败**，这是想要的——留一个静默别名等于留一条没人维护的第二条路。

## 还没做

- `picker` 的滑块与开关**画不出来**：`kind` 已经能解出、能 round-trip，`widgets/picker.rs` 仍然只画菜单。
- `input` 数字框的内联 `−` / `+`：`input` 不承担区间了，手势层也就没动；原生 spinner 依旧按不到。
- `input.dir`（加减按钮的朝向）、`picker` 开关的 `on` / `off` 两个标签。
- `color` 不并入 `picker`：它的值是 `L C H` 三元组，不是三种 kind 里的任何一种，域不同就仍是独立节点（ADR 0052）。

## 代价

- wire 是破坏式的：`type: select` 不再解码，`input` 也不再接受带区间的 `kind`。示例、reflux 的 SDK 与 demo 同
  一批改完。
- 值从字符串变成数字/布尔这件事现在落在 `picker` 上：宿主的成员表要认三种类型，而不是一种「都是字符串」。
- 菜单、滑块、开关三者的参数都在同一个 `kind` 里，读代码的人得记住「哪个分支对应哪个组件」——这是省词表的账，
  记在 §一 的表格里。
- 开关只有两态，和「从一组里挑」的语义只在上限为 2 时重合；别让人以为菜单的选项数量可以随手从 5 改成 2 而不改
  `kind`。
- 名字 `picker` 与 `color`（颜色选择器）在口语上重叠；但后者的域不是三种 kind 之一，仍是独立节点，这条重叠只在
  人说「picker」时需要用上下文消解。
