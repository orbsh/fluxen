# 0050 — 值的三种类型，两种控件各自给出该类型的手势

状态：Proposed（未实现，先记下）

## 问题

`input` 与 `select` 各自只认一种值：

- `input` 的 `kind` 是 `JsType`（`text` / `number` / `bool` / `password` / `button` / `submit`），但只有 `text` 与
  `bool` 有像样的手势——`bool` 画成一个带勾的方框（`<svg>` 那个），而 `number` 只是把 `type="number"` 交给浏览器：
  原生 spinner 的加减按钮在大多数系统上只有 12px 高，按不到，页面上等于没有加减。
- `select` 没有 `kind`：它永远是选项行，一行一个。数字、布尔借道 `select` 时只能假装成字符串。

于是"调一个数字"和"开关一个布尔"在页面里有两副面孔，挑哪副面孔靠页面自己拍，且没有一套写法能说清"我要这个数的
上下限是多少"。三种值类型 × 两种控件，本该是一张表，而不是每次重新发明。

## 决定

一根轴：**值的类型**（`kind: text | number | bool`），两种控件各自给出该类型最自然的手势：

| 值的类型 | `input` | `select` |
|---|---|---|
| `text` | 文本框 | 菜单（可展开，ADR 0049 的 `expand`） |
| `number` | 数字框 + 内联 `−` / `+` | 滑块 |
| `bool` | 勾选框 | 开关 |

三条推论：

- **控件只改手势，不改值**。`number` 发 JSON 数字，`bool` 发 JSON 布尔，`text` 仍发字符串。一个字段的值只有这
  三种形状，宿主两侧（校验器、持久化）按类型接，不按控件接。
- **`dir` 对两种控件都成立**：`input` 的加减按钮在框里还是框下、`select` 的选项或滑块是横是竖，由它说。它是
  排版，不是语义。
- **仍是两个节点，不新增类别**：`input` 与 `select` 都已是字段（ADR 0031/0032），`kind` 只是它们的属性。出口、
  时机、`tag` 一条都不变。

要补的属性：

| 节点 | 属性 | 用于 | 缺省 |
|---|---|---|---|
| `input` | `dir` | `number` 的加减按钮朝向 | `row`（在框的右侧） |
| `input` | `min` / `max` / `step` | `number` 的范围与步长 | 不设 = 不限制；`step` 1 |
| `select` | `kind` | 三值之一 | `text`（现在的行为） |
| `select` | `min` / `max` / `step` | `kind: number` 的滑块 | 见下文「未定」 |
| `select` | `on` / `off` | `kind: bool` 开关的两端标签 | 用选项的前两个 id；没有就用「开 / 关」 |

## 未定

- **滑块的边界**：(a) `min`/`max` 必填，缺省时退回数字框；(b) 缺省 0–100、步长 1。倾向 (b)：滑块没有边界没有
  意义，而 0–100 是最常见的猜测；选 (a) 的话"忘了写边界"会静默降级成另一种控件，难查。
- **开关的两种状态能不能各带一个节点**（现在打算只带一个标签字符串）。若将来要"开=启用/关=停用"这种带图标
  的两端，形状会变。

## 记录时的现状（写完这一条不等于做完）

- `input` 的 `text`、`bool` 有手势；`number` **没有**内联加减；`password` / `button` / `submit` 三个 `JsType` 值
  是旧词汇，本轮不动。
- `select` **没有** `kind`；`dir` 与 `expand` 已经在了（ADR 0049），`multiple` 也在。
- 设置页的三个长度令牌（`round` / `input-round` / `border-width`）现在是 `text` 框 + 字符串成员；换成 `number`
  会让成员变成数字，服务端的值域校验要跟着认两种写法。

## 代价

- 值从字符串变成数字/布尔，宿主的成员表要认三种类型，而不是一种"都是字符串"。设置页现在就靠字符串成员
  （`"10"` → `10px`），换 `kind` 要同时改校验与落盘。
- 数字框的内联加减是一个渲染器行为（点一下 ± `step`），它得先回答"空值加一次是多少"——缺省从 `min` 起，没有
  `min` 就从 0 起。
- 开关只有两态，和"从一组里挑"的语义只在上限为 2 时重合；这不是问题，只是别让人以为 `select` 的选项数量可以
  随手从 5 改成 2 而不改 `kind`。
