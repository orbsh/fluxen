# ADR 0019: 拖拽的两个角色——grab（源）与 dock（落点）

状态：草案（2026-10-28 用户确认方向，待实施）
日期：2026-10-28
仓库：fluxen

## 背景

需求是液态化文档里那一下「按住一条消息往旁边一拖，它离开主河，变成一个独立的小流」
（`~/.hermes/wiki/liquefaction.md` §界面）。渲染器今天表达不出来。

上行面只有五处：`input`／`textarea` 回车、`select` 点选项、`form` 的 submit 按钮、
`canvas`／`chart`／`editor` 模块的 `host.send`、`forcegraph` 的 `node-click`。`rack`
的行、`text`、`fold` 的头都上不了行；`forcegraph` 里的拖是相机与节点物理，松手没超过
阈值才算点击，拖本身不上报。

所以「拖一下」在词表里无处表达。它不是某个组件的本地态——源和落点中间隔着别的节点；
它也不是「某类元素缺个属性」——属性是修饰，而这里要的是一个角色（一块可以落东西的
地方、一个可以被提起的东西）。

ADR 0008 §5 立过一条：「组件内瞬态交互（hover/focus/drag）：无跨组件消费者，不进
任何槽，归组件内部信号，wire 不认识它。」那条成立的前提是**无跨组件消费者**。pin 有
消费者——生产者要据此建一条流——所以它是事件；而它的瞬态部分（谁在飞、落在哪）第一次
是跨组件的。这条 ADR 因此同时是一次分型，和一次对 0008 §5 的定点例外。

## 决策

新增两个根变体（都是包装型），外加渲染器内部一个页面级拖拽会话。

1. **`grab`（源）**：`attrs: ClassAttr`（class／selector）；`bind["value"]` 可选——
   声明了就是「这件货物」，取值与 `input` 的 default 同族（`default` 静态值／`source`
   槽／`local`）。`children` **可选**，于是有两种形态：

   - 有 `children`：整块可拖（卡片、缩略图这类非文本块）。
   - 无 `children`：**提手**。渲染器给一条细抓柄，货物在 `bind.value` 上，展示留给同级
     的兄弟节点。信息流的行用这一形态——它顺带解决「按住拖」与「选中一行文字」的冲突，
     而且不会把同一段文字在 wire 上存两份。

   名字说的是角色（可以被提起的东西），不是手势。

2. **`dock`（落点）**：`children` = 已放下的内容（生产者随后往里追加钉住的流）；
   `attrs: DockAttr { class, selector, expand }`，`expand` 是闭枚举 `reveal`（默认：
   常态一条细条，拖拽在飞时展开）／`reserved`（始终占好位）；`bind["value"]` 为
   `Event { event }` 或 `Local { slot }`——事件名与落点身份在这一侧定义，于是多个 dock
   天然可分（不同 dock 绑不同事件名即可）。名字说的是位置（停靠处）。

3. **上行一帧，由 `dock` 发射**：
   ```
   Outflow { event: <dock 的事件名>, id: <dock 的 id>,
             data: { item?: <grab 的 id>, value?: <grab 的载荷>, meta?: <dock 的 bind.default> } }
   ```
   空即无（ADR 0012）。由落点发射的三条理由：drop 事件本来就落在 dock 的 DOM 上，
   emit 就在处理它的那个函数里，不需要跨组件回调；帧的 `id` 惯例是「发射节点自己的 id」，
   于是它等于落点，正好对上宿主按事件名注册的那一侧；「被拖来的是什么」是货物不是地址，
   进 `data`（`forcegraph` 的 `node-click` 已是同款：实体信息全在 `data`）。
   约定生产者至少给 `item` 或 `value` 之一，两个都没有的这一帧没有可用信息——门里钉住。
   `Local` 绑定时写进槽的包装与上行同形（ADR 0010），所以整条链可以纯前端闭合。

4. **页面级拖拽会话（`Ctx` 内部，只在本页内存，不上线）**：`dragstart` 把 `grab` 的
   描述符（id、载荷取值）放进会话；`dock` 在 `dragenter`／`dragover` 时登记自己并
   `preventDefault`；`drop` 时由 dock 取出会话里的 grab 描述符、组帧发出；`dragend`
   清空。这份状态不进任何槽——它是浏览器的事实（谁在飞、悬在谁上面），不是生产者的树。
   发射逻辑因此只有一份、在 dock 侧；`grab` 不参与上行，`dragstart` 之后什么都不做。

5. **三态与几何**：常态（`reveal` = 细条，`reserved` = 占位）／拖拽在飞（全局展开，
   让人先看见「能放这」）／悬停在上（高亮 + 展开）。零宽的盒子没有命中区，所以「拖到
   区域才展开」按字面做不到；正确顺序是 `dragstart` 全局展开、悬停只做高亮。展开走
   覆盖层或只变宽且不参与流式排布——否则光标下面的内容会移走。

6. **载荷纪律**：`grab` 带的是声明时的快照，渲染器不校验它与槽里的值是否一致（同
   `input` 的 default 与 value 的关系：一致性是生产者的编排责任）。所以流式行优先带
   小键，值大的留在生产者侧自己取。

7. **列表里不共享 grab**：`rack` 的 `item` 只是壳——模板自己的 `children` 会被整段换成
   那一个行节点，所以模板能留的只有类型与 attrs 这类壳信息。要在一行里放 grab 和文字两
   件事，它们在行节点内部（行自己是个 `case`），不在模板里。机制与那个「叶子类型当模板
   会静默吞掉行」的坑见 ADR 0020。
   grab 因此不进模板、不被所有行共用，身份与货物天然每行不同，也不存在「从内部子节点里
   找身份」那套查找，更没有被包的容器里「能装几个元素」这种问题。
   代价两条，都接受：模板复用的少了，版式随每行送一遍（本来就要送行内容，增量只是
   每个 grab 的一个 id 或一小份载荷）；以及「货物与展示同源」时同一段内容会存两份
   ——提手形态没有这一份，所以信息流用提手。

## 后果

- 根变体 30 → 32：`struct` + `enum Accrete` 的 arm + `ui_leptos` 分派 + 三个宏 derive
  （`AccreteOps`／`ClassifyAccrete`／`ClassifyAttrs`）；schema 自动跟随（`stage schema`
  不用手改），老帧零影响（新增 arm）。
- 拖拽会话是新东西：它是渲染器里第一份**跨组件**的瞬态态。要在 `Ctx` 上加、要在
  ADR 0008 §5 的例子里写清边界（只有会话，不写槽、不上线），并且只能有一份——两个
  组件各自维护自己的拖拽状态就是这条设计的反面。
- `grab` 的提手形态需要一个默认外观（细抓柄），否则不带 class 的帧里它就是一条看不见
  的边；样式仍由 class 覆盖。
- 回归样本：`examples/yaml/` 加一份「模板只给壳 + 行里带 grab + 静态 dock」的帧；
  `cargo test`／`cargo check -p ui_leptos` 是仓库自己的门，浏览器那一层（真实拖拽一次、
  恰好一帧、`data` 的三个可选键、落点类加了又撤）挂在 reflux 的 gate 套件里或另起一份
  ——fluxen 自己没有 CDP 门，这条限制照实记。

## 明确不做的替代方案

- **容器属性法**（给 `case`／`rack`／`group` 加 `drop` 属性）：要加到每个容器才可组合，
  而每个不需要拖拽的容器都背上一条语义；属性同样是闭白名单，省下一个变体换来 n 处
  语义与「这个容器到底能不能落」的判断。角色分型是 accrete 既有的形状
  （case／rack／fold／float／layer／portal／pages 各是一个角色）。
- **复用 `bind` 加一个 `drag` 键**（不动词表）：`bind` 的键是组件自己的语义
  （value／select／field／theme），drag 不是哪一类组件的语义；而且每个渲染函数都要
  各读一遍，比一个变体贵。
- **生产者自绘 canvas 模块**：等于自己重画整个信息流——`rack` 的追尾滚动、文本选择、
  无障碍全丢，而且模块看不见自己之外的落点。
- **每行打 DOM 标记、由页面脚本代劳**（框架 runtime 那套）：把渲染器自身的能力外推给
  每个使用方各写一遍，且身份要从 DOM 里读回来（读回来的是猜，不是树）。组件实例的
  闭包里本来就有身份与载荷，没必要出 DOM 再进来。
- **模板里放共享的 grab**（第一版设想）：模板是共享的，静态货物会被所有行共用；补救
  办法是「从包住的子节点里取身份」，那是内部查找，且要回答「里面装几个元素」这类问题。
