# ADR 0019: 拖拽的两个角色——grab（源）与 dock（落点）

状态：已接受（2026-10-28；accrete 与 ui_leptos 已落地，浏览器门待下一轮）
日期：2026-10-28
仓库：fluxen

## 背景

需求是液态化文档里那一下「按住一条消息往旁边一拖，它离开主河，变成一个独立的小流」
（`~/.hermes/wiki/liquefaction.md` §界面）。渲染器今天表达不出来。

上行面只有五处：`input`／`textarea` 回车、`select` 点选项、`form` 的 submit 按钮、
`canvas`／`chart`／`editor` 模块的 `host.send`、`forcegraph` 的 `node-click`。`rack`
的行、`text`、`fold` 的头都上不了行；`forcegraph` 里的拖是相机与节点物理，松手没超过
阈值才算点击，拖本身不上报。

所以「拖一下」在词表里无处表达。它不是某个组件的本地态——源和落点中间隔着别的节点；
它也不是「某类元素缺个属性」——属性是修饰，而这里要的是一个角色（一块可以落东西的
地方、一个可以被提起的东西）。

ADR 0008 §5 立过一条：「组件内瞬态交互（hover/focus/drag）：无跨组件消费者，不进
任何槽，归组件内部信号，wire 不认识它。」那条成立的前提是**无跨组件消费者**。pin 有
消费者——生产者要据此建一条流——所以它是事件；而它的瞬态部分（谁在飞、落在哪）第一次
是跨组件的。这条 ADR 因此同时是一次分型，和一次对 0008 §5 的定点例外。

## 决策

新增两个根变体（都是包装型），外加渲染器内部一个页面级拖拽会话。

1. **`grab`（源）**：四个字段——`id`、`kind`、`payload`、`children`。没有 `attrs`、
   没有 `bind`：它是一层**不加样式、不占位**的包装（不设 padding／边框／背景，也不
   消费额外尺寸，尺寸全由 `children` 给），只说两件事——这件东西可以被拖走，它的货物
   是什么。

   - `payload` 是货物本身，任意 JSON，原样进上行帧；`kind` 是货物标签，供落点配对。
   - `id` 是**行身份**：`rack` 的 keyed diff 用行节点自己的 id，没有就退 `#{idx}` 位置键，
     中间删一行会让后面所有行重建、本地态丢。grab 是无样式包装，可以当行的根节点，所以
     id 落在这里。渲染器**不替它从子节点借 id**：那会造出两个同 id 的节点，按 id 定位的
     行操作（`append`／`remove`／`patch`）从此指向不明——身份只能生产者给。

   名字说的是角色（可以被提起的东西），不是手势。

2. **`dock`（落点）**：`children` = 已放下的内容（生产者随后往里追加钉住的流）；
   `attrs: DockAttr { class, selector, expand, accept }`：

   - `expand` 是闭枚举：`reveal`（默认，常态一条细条，拖拽在飞时展开）／`reserved`
     （始终占好位）。缺省不写进 wire。
   - `accept` 是收哪些 `grab.kind`：缺席 = 全收（只有一个落点时不必写）；写了就是闭集合
     比对，没有 `kind` 的货配不上任何写了 `accept` 的落点，落上去等于没落（不发射、
     不高亮）。

   `bind["value"]` 为 `Event { event }` 或 `Local { slot }`——**事件名与落点身份在这一侧
   定义**，于是多个 dock 天然可分：事件名不同就是不同的落点，帧的 `id` 是哪个 dock 收的。
   名字说的是位置。

3. **上行一帧，由 `dock` 发射**：
   ```
   Outflow { event: <dock 的事件名>, id: <dock 的 id>,
             data: { id?: <grab 的 id>, kind?: <grab 的 kind>, payload?: <grab 的 payload> } }
   ```
   空即无（ADR 0012）。**`data` 里不换名**：`grab.id` 就叫 `id`。帧外层那个 `id` 是
   发射节点（落点）的，`data` 是自由对象，两者不冲突——对面看到的名字和发出去的名字
   是同一个，后端不需要为同一件东西定义两套字段。
   由落点发射的三条理由：drop 事件本来就落在 dock 的 DOM 上，emit 就在处理它的那个函数
   里，不需要跨组件回调；帧的 `id` 惯例是「发射节点自己的 id」，于是它等于落点，正好对上
   宿主按事件名注册的那一侧；「被拖来的是什么」是货物不是地址，进 `data`（`forcegraph`
   的 `node-click` 已是同款：实体信息全在 `data`）。
   `Local` 绑定时写进槽的包装与上行同形（ADR 0010），所以整条链可以纯前端闭合。

4. **页面级拖拽会话（`Ctx.drag`，只在本页内存，不上线）**：`dragstart` 把 `grab` 的
   货物（`id`／`kind`／`payload`）放进会话，`dragend` 清空；`dock` 在 `dragenter`／
   `dragover` 里按自己的 `accept` 判断并 `preventDefault`（只挡其中一个，浏览器仍会
   把这次释放当成「不可落」，drop 根本不触发）；`drop` 取出会话里的货物、组帧发出、清空
   会话。落点不需要在会话里登记自己——drop 事件落在它的 DOM 上，自己的处理器里就有 id、
   事件名与元数据；会话只需要「谁在飞、带什么」。这份状态不进任何槽：它是浏览器的事实，
   不是生产者的树，而且只能有一份。

5. **三态与几何**：常态（`reveal` = 细条，`reserved` = 占位）／拖拽在飞（`dock-armed`，
   全局展开，让人先看见「能放这」）／悬停在上（`dock-over`，只做高亮）。零宽的盒子没有
   命中区，所以「拖到区域才展开」按字面做不到；正确顺序是 `dragstart` 全局展开、悬停只做
   高亮。展开在覆盖层里长（`.dock-panel` 绝对定位），落点自身的占位宽度不变——否则光标
   下面的内容会移走。类名是唯一随拖拽状态变的东西，子树只建一次（重建会丢滚动与本地态）。

6. **载荷纪律**：`payload` 是生产者写的字面快照，渲染器不校验它与任何槽是否一致——一致性
   是生产者的编排责任（同 `input` 的 default 与 value）。所以流式行优先带小键，值大的留在
   生产者侧自己取。

7. **列表里不共享 grab**：`rack` 的 `item` 只是壳——模板自己的 `children` 会被整段换成
   那一个行节点，所以模板能留的只有类型与 attrs 这类壳信息。要在一行里放 grab 和文字两
   件事，它们在行节点内部，或者 grab 自己就是行的根节点。机制与那个「叶子类型当模板会
   静默吞掉行」的坑见 ADR 0020。
   grab 因此不进模板、不被所有行共用，身份与货物天然每行不同，也不存在「从内部子节点里
   找身份」那套查找。
   代价一条，接受：模板复用的少了，版式随每行送一遍（本来就要送行内容，增量只是每个
   grab 的 id／kind／payload）。

## 后果

- 根变体 30 → 32：`struct` + `enum Accrete` 的 arm + `ui_leptos` 分派 + 三个宏 derive
  （`AccreteOps`／`ClassifyAccrete`／`ClassifyAttrs`）；schema 自动跟随（`stage schema`
  不用手改），老帧零影响（新增 arm）。`grab` 不领兜底 id（合成的 `grab-N` 进不了帧），
  `dock` 领（它要发帧，所以帧的 `id` 不会空）。
- 拖拽会话是新东西：渲染器里第一份**跨组件**的瞬态态。已在 `Ctx` 上加（`Ctx.drag`），
  边界写在字段的注释里（只有会话，不写槽、不上线），并且只能有一份——两个组件各自维护
  自己的拖拽状态就是这条设计的反面。
- web-sys 的两个 feature 进了 workspace（`DragEvent`／`DataTransfer`，后者不带就取不到
  `dataTransfer`，Firefox 也不会起拖）。
- 源那边没有样式（它只是包装），样式全在落点：`main.css` 的 `.dock*` 四条规则。
- 回归样本：`examples/yaml/21.drag.yaml`（两行 grab 当行根 + 两个 dock：一个 reveal 收
  `message` 发 `pin` 带元数据，一个 reserved 只收 `note`）。`cargo test -p accrete` 覆盖
  两侧的 wire 形状（含默认值不进 wire、闭枚举拒绝域外值）；`cargo check -p ui_leptos`
  （host 与 wasm32 各一次）覆盖分派。浏览器那一层——真实拖拽一次、恰好一帧、`data` 的
  四个可选键、类名加了又撤、配不上的落点静默——挂在 reflux 的 gate 套件里或另起一份；
  fluxen 自己没有 CDP 门，这条限制照实记。

## 明确不做的替代方案

- **容器属性法**（给 `case`／`rack`／`group` 加 `drop` 属性）：要加到每个容器才可组合，
  而每个不需要拖拽的容器都背上一条语义；属性同样是闭白名单，省下一个变体换来 n 处
  语义与「这个容器到底能不能落」的判断。角色分型是 accrete 既有的形状
  （case／rack／fold／float／layer／portal／pages 各是一个角色）。
- **复用 `bind` 加一个 `drag` 键**（不动词表）：`bind` 的键是组件自己的语义
  （value／select／field／theme），drag 不是哪一类组件的语义；而且每个渲染函数都要
  各读一遍，比一个变体贵。
- **生产者自绘 canvas 模块**：等于自己重画整个信息流——`rack` 的追尾滚动、文本选择、
  无障碍全丢，而且模块看不见自己之外的落点。
- **每行打 DOM 标记、由页面脚本代劳**（框架 runtime 那套）：把渲染器自身的能力外推给
  每个使用方各写一遍，且身份要从 DOM 里读回来（读回来的是猜，不是树）。组件实例的
  闭包里本来就有身份与载荷，没必要出 DOM 再进来。
- **grab 从子节点借 id**：包装层自己没 id 时拿第一个子节点的 id 顶上，看着省事，实际
  会造出两个同 id 的节点（子节点还占着它），而列表的行操作按 id 定位——从此指向不明。
  身份只能由生产者给，落在行的根节点上。
- **模板里放共享的 grab**（第一版设想）：模板是共享的，静态货物会被所有行共用；补救
  办法是「从包住的子节点里取身份」，那是内部查找，且要回答「里面装几个元素」这类问题。
