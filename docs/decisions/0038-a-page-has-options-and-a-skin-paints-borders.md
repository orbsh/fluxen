# 0038 — A page has options; a skin is how a border is painted

Status: **Accepted** (2026-11-24). Revised the same day: an option is a slot with two halves (§2), and the
page may own its own half (§5) — the `config` op, `Ctx.config` and `set_config` are gone.

Two things a frame cannot say today: where a page-level option lives, and who decides how a border is painted. The first was answered by an accident of history — `inject` wrote page values from the far side, and ADR 0031 had already ordered it deleted. The second was never asked at all: `border: var(--border)` was the only way a border could be drawn.

---

## 1. `inject` is gone (ADR 0031 §2, finally)

ADR 0031 §2 says "`source` / `sink`; delete `report` and `inject`". `report` was executed — `both` is what it said. `inject` was not: it kept a `Content::Inject` variant, a consuming arm in `ui_core`'s dispatch, an equal-value guard with three unit tests, an example frame and three phrases in the wire documentation, and this repository has since been read twice as if its status were the other one ("nobody uses it" and "the mechanism exists").

Deleted in this change: the variant and `InjectOp`, the dispatch arm, `inject_writes` (the guard that existed only for its equal-value rule), `content/tests/inject_op.rs`, `examples/yaml/00.inject.yaml`, and the action list, the table row and the symmetry sentence in `docs/external-integration.md` and its `.zh-CN` twin. ADR 0011 is marked retired and keeps its record; the stale `inject` mentions in `docs/ideas/emergent-ui.md` now name the in-page write instead.

What is lost with it, stated now rather than discovered later: **the far side can no longer plant a page-local assignment.** ADR 0031 §1 gave every value one address whose `scope` says who is authoritative (a read is a `source`, a write a `sink` — one type each since ADR 0039), so the far side still has a door — `set` writes the slot's node, and a `both` read takes it as the fallback (`tiles` builds exactly that `source` for its `step` slot, tiles.rs:481-489, so `set slot: page, data: {type: text, source: {default: home}}` moves a window). What it cannot do any more is *outrank* the page: `value_of` reads the local assignment first (hooks.rs:107-111), so a remote `set` decides only while the page has not chosen, and after the first in-page click that slot is the page's. `inject` was the exception that could overwrite the local half; the exception is gone, the asymmetry ADR 0031 described is now the whole rule. A page option (§2) is a value in a slot like any other; the far side keeps writing it with `set`, and the page's own half is the ordinary local one.

## 2. An option is a slot with two halves

A page option is a value: no row identity, no node tree, and it has to be answerable as a whole — "what is this page configured as" dumps to one object. Everything an option needs already exists for a value in a slot: the far side writes the data plane, the page writes its own half, and a `both` read takes the page's member first and the far side's behind it (ADR 0031 §1). So options are **one slot**, not a namespace of their own.

**Decision.** The page's options live in ONE slot whose name the mount options give (`config`, ADR 0045) — absent means `__CONFIG__`, an empty string means this page has no options — holding ONE object whose members are the options. Members are decided **member by member**: the local plane first, the data plane behind it, so a control that owns `sketch` leaves `density` to the producer. `Ctx::config_get(member)` is that read; `Ctx::mirror_config` (§3) reads the same merge.

Two writers, both ordinary:

- **The far side** — `set` (the whole object) or `patch` (one member) on the config slot, in the same stream as the `create` that builds the page. `patch`'s rejection semantics apply, so the object has to be `set` before a member is patched, and there is no equal-value guard: a redundant write notifies its readers.
- **The page** — a `sink` that names a `path`. `emit` writes the payload INTO the local plane at that path, merging; `sink: {dest: __CONFIG__, scope: local, path: /}` is a checkbox that owns one member and knows nothing about the others — it is a loom now, because a field has no sink (ADR 0032 §2): `{type: loom, attrs: {submit: [change]}, sink: {dest: __CONFIG__, scope: local, path: /}, children: [{type: input, tag: sketch, kind: bool}]}` packs `{sketch: bool}` and `path: /` merges those members into the object. A `null` at one segment drops that member, handing it back to the far side. A sink with **no** path keeps the event shape (`{dest, id, data}`) — that is what a slot used as a message channel carries, and pages read it back with `path: /data`.

This is one capability, not a config special case: a sink may address inside the local value, which is the same `path` a `source` already reads with.

**Where the object rides.** A slot's value is the node's **payload** — `source.default` (ADR 0012: no payload means the empty value) — so the far side sends one node whose payload is the option object, and a reader spells the member plainly: `source: {slot: __CONFIG__, path: /sketch, scope: both}`. A path read resolves against the node's wire shape first and its payload second (`hooks::value_of`), which is what lets one path name a member in both planes: the page's half is a plain value, the far side's is a payload on a node.

**A switch is not a buffer.** A text field never reads the slot it writes — an echo would undo the keystroke — so its exit is Enter. A `bool` field is a different kind of control: its value *is* its display, and a write is idempotent (checked = value), so it needs no Enter to press. What differs is the **trigger**, not the channel: a loom holding a `kind: bool` field names `submit: [change]` and its change is its exit (ADR 0032 §3).

What it costs, stated: **one signal for the whole option object** — a write to one member reruns every reader of the object, where the retired per-option signals reran only that option's readers (with a handful of page options that is the cheaper trade, and it is why the object is one slot); and **one reserved-looking name in the application's slot space**, which the mount option `config` is the escape from — the default is `__CONFIG__` precisely because no application would name anything that.

History, for the record: this replaced `action: config` + `Content::Config`/`ConfigOp`, `Ctx.config` (`config` op merged per member, wrote only the remote half, dropped equal values), `ConfigSlot`/`ConfigValue`, `set_config`, and the per-option mirror effects. Nothing outside this repository ever sent a `config` frame.

## 3. A skin is how a requested border is painted

A frame asks for a border with a class — `is-border` (core.css:957) — and has never asked how it is drawn. That is the seam: the `sketch` member of the option object chooses the paint. Absent, `false` or no option slot at all means `normal`, which is exactly the old rendering — no extra node, no observer, no branch taken.

Mirroring to CSS: the option object becomes `data-<member>` attributes on the document root — one effect for the slot, one attribute per **scalar** member of the effective value (the page's over the far side's). A member that disappears takes its attribute with it, and an attribute the mirror never wrote is never touched. `sketch = true` yields `html[data-sketch="true"]`; an object or an array member is not mirrored, because an attribute is one text. The boot installs the mirror through one `ui_core` helper, because the page shell is the boot's business (ui-core/src/lib.rs states that split) and a host that replaces the boot (prism, reflux) calls the same line. Nothing is per-option code, and the whole option set is visible as attributes — to devtools and to CSS alike.

What the skin changes in CSS, and only that, in `core.css` — a skin is core's own state (it sits with the `.is-*` family in the `utilities` layer), not something a page does to itself. `custom.css` is the page's file: it exists so an application can override the look, and a framework feature parked there would be the framework overriding the application.

- The border keeps its space and loses its paint — `border-color: transparent`. Nothing moves when the skin flips, which is the only reason a drawing is allowed to exist.
- `--round` and `--input-round` go to `0`. The drawing owns the shape; `.is-border.round` sets `overflow: hidden` (core.css:960-963), so a rounder CSS corner would clip content against a shape nobody drew.
- Colours are untouched. `--fg` is `light-dark()` (core.css:77), so one skin draws ink on paper and chalk on a blackboard without knowing that dark mode exists.
- The painted shadow goes wherever the pen draws one: a blur cannot be sketched, so the skin casts its own (a second outline, §4).

It has to be the `utilities` layer, and that is not a style preference: `.is-border`'s `border: var(--border)` is declared there (core.css:957), and layer order decides before specificity — the same rules written into `components` would lose however specific the selector got.

## 4. A sketched border is drawn from geometry

Attach: one helper, called by the widgets that own a bordered box and can hold children — `frame`, `panel`, `loom`. It renders one extra child when the skin is sketch: an `<svg>` inset by one border width (`calc(-1 * var(--border-width))`, so it covers the border box rather than the padding box), `overflow: visible` (a stroke that spills a pixel past the box is the tell, and clipping it would erase the point), `pointer-events: none`, painted last so the stroke rides the box edge.

Every widget that paints a border of its own is attached, not only the ones the page marks. `frame` and `panel` carry the layer as an ordinary child. `input` cannot: it is a **void element**, so the drawing gets a host one level out — a `span.rough-host` that is `display: contents` until the skin is on (normal mode keeps no box of its own and lays out exactly as before), and that in sketching carries the node's box, the layer, and the child's edge (the field's own `border-color` goes transparent, its padding and background stay). `textarea` uses the same host. `button` holds its drawing itself, which needed `attrs.class` to be plumbed instead of the hard-coded class — the one-line fix this ADR had already recorded. `select` is a div whose rows rebuild on every choice, so the layer is a child of the box and the rows are a fragment inside it: a choice re-picks rows, never the drawing. A select whose box has no height draws nothing, which is the same rule every empty box follows.

Two things about that host are layout, not decoration, and both were wrong at first:

- **The host takes the field's place in the layout, so it must be block-level.** An inline host shrink-wraps its child, and since the drawing follows the host, every field drew itself at the width of its intrinsic content — a field in a wide column came out 170px wide and that was reported as "the width is fixed". `display: flex` on the host, `width: 100%` on the child: the field fills what it is given, exactly as it did with no host at all.
- **A switch is the one field that does not take the width it is offered.** It is a box of its own size, so the host carries `is-checkbox` (a class, not `:has()` — the host has no attributes of its own and one more selector language is not worth it): `flex: 0 0 auto`, `align-self: center`, `width: fit-content`, and the child keeps `1.15em`. Before this, a `bool` field carried the same `flex` class as every other field, which made a checkbox a growing flex item — a full-width bar with the tick floating in the middle of it.

A shadow is drawn too, and this one is not the same argument but its inverse: normal mode's shadow is a **blur** (Tailwind's two-layer `shadow` in `.is-shadow` — `0 1px 3px` over `0 1px 2px`, lifting to `shadow-md`), and a blur is the one thing a pen cannot draw, so the skin answers in the vocabulary it has: the box drawn a second time, offset, in a lighter ink — `g.shadow` at `opacity: .35` and `translate(2px, 2px)`, cast behind the edge by document order, stepping out to 4px on a button's hover where the soft pair grows too. Where the pen draws a shadow the painted one goes (`:is(.is-border, .button, .select).is-shadow, .rough-host .is-shadow { box-shadow: none }`): a crisp digital offset sitting next to a drawn one is the "two hands" defect this section keeps refusing. It is also what wired.js does — nothing in a sketch is blurred, so nothing in the skin may be either.

A scrollbar is the one surface with no element behind it: it cannot host the layer, and the sheet cannot ask Rust for a drawing, so it is the one place where the pen is a picture rather than a path. What the skin paints is the thumb's background — a tiled zigzag (`\/\/\/`, a tape squashed into its own edge) whose tile repeats down the track instead of stretching, since a stretched zigzag is one long diagonal. Three of its properties were found by measuring, not by reading. Scrollbar pseudo-elements take neither `mask` nor `clip-path`: both parse, neither paints, and the thumb stays a solid slab — so the ink has to live inside the image, which means writing it twice, once per scheme, because a background image cannot read `--fg`. And the standard properties **win** over the pseudo-elements in Chromium: `body` standardises the page with `scrollbar-width: thin` (core.css:115), and under that the pseudo-elements are silently switched off, so the skin hands them back to the UA (`auto`) and only then can anything be drawn. Gecko never had the pseudo-elements, so it gets `scrollbar-color` behind a `@supports not selector(::-webkit-scrollbar)` guard: a thin bar in the page's ink, never a drawing it cannot make.

A shadow is covered by the box that casts it, and a stroke laid *over* the box is covered by nothing: drawn as-is, the same outline shifted two pixels is a doubled edge, and that is the first thing the eye catches. So the shadow is clipped to the outside of the box — an even-odd `clipPath` in `defs`, one per layer, id from the seed, hole exactly the box. The clip sits on a wrapper one level out from the CSS offset, and that nesting is not tidying: a clip on the same element the offset applies to travels with the offset, the hole follows the shadow, and nothing is covered at all (measured — that shape erased the shadow entirely). With the wrapper, ink inside the box is 0 where it was 117 and 73 pixels on the top and left edges, and the outside is unchanged at 36 and 150.

The tick is drawn too, and that is the same argument one level down: a switch's content is a **stroke**, while the CSS version is a filled `clip-path` glyph — a second hand in the middle of a hand-drawn box. `path.check` rides in the layer with the edge and the selected mark, same pen and same `currentColor`; it exists from the first drawing and the stylesheet decides when it shows, because `:checked` is state CSS can see for itself (the same reason `path.mark` waits on a class rather than a signal). Under the skin the painted glyph is switched off (`::before { content: none }`), so the box holds one tick and not two.

The seed is per node, not per page. `seed_for` hashed the node's id, and a node without one hashed the empty string — so every box the page did not name came out as the identical drawing, retraced stroke for stroke, which is exactly what a row of buttons showed. A counter, advanced once per layer and mixed with whatever identifies the node (SplitMix64's finaliser over a straight odd step), makes the wobble a property of the box instead of a property of the page holding one box. It is still not the size — a resize must redraw the same hand — and it is deliberately not stable across a rebuild: a node that a layout update rebuilds draws itself again, which a hand-drawn page is allowed to do and a table of coordinates would not.

Paint lives in the stylesheet, not on the element: `attr:stroke` written in a `view!` on `leptos::svg::path()` emitted nothing (measured — the rendered `<path>` carried `d` alone and computed `stroke: none`), and there is no reason to fight it. The pen is declared once in `core.css` (`fill: none; stroke: currentColor`, round caps and joins), with the weight on the kind of element: `path.edge` at 1px, `path.mark` at 1.25px, `path.check` at 1.1px. That keeps the ink colour out of Rust, where it would be a second truth.

Geometry: `roughr` 0.14 draws the primitive from the host's border-box size, read by one `ResizeObserver` per sketched node (the pattern in canvas.rs:399). `Drawable` exposes `sets` and no serializer, so the op→`d` adapter (~40 lines) is ours. A rebuild happens only when the measured size moves by ≥0.5px. The seed is per node (a field hashes its `tag`, else its `id`; anything else its `id`, else a mount counter) and never per size, so consecutive frames are pixel-identical and only a resize re-rolls the wobble.

Paint: every path is stroked with `fill: none; stroke: currentColor` at 0.75px, so the stroke inherits the colour the page already gave that element and reads lighter than the CSS border it replaces. One tracing of a rectangle reads as a traced shape, not as a hand — so the edge is drawn by two hands, the seed and the seed stirred (`rotate_left(17) | 1`, never zero, since zero means "pick one for me"), which puts four edges × two tracings into two path elements. **Two tracings is the whole budget**: `roughr` traces each line twice of its own accord, so the second hand sets `disable_multi_stroke` — an edge gone over four times stops looking sketched and starts looking bold, which is the one thing a pencil border must not do. This is the half `roughr` does not deliver: it hands back a baked colour, and a baked colour cannot follow `light-dark`. We take the geometry, we paint with `currentColor`.

**Selected is said in the same hand.** A heavier frame would claim selection in a voice the page does not otherwise use, so the mark is an L in the right-bottom corner — down the right edge, along the bottom, three pixels outside the box — traced by the same two hands and therefore doubled and slightly uneven, like a corner gone over with the pencil. It weighs 1.25px against the edge's 1: the difference is legible and the frame does not appear. Which boxes show it is a stylesheet fact (`path.mark` starts at `opacity: 0`; `.is-border.selected > svg.rough path.mark` brings it to 1), so nothing in script watches a class: the same layer serves both states, and re-selecting re-paints nothing.

Until the first size arrives the CSS border is still painted; the host carries `data-rough="ready"` once the drawing exists, and only then does the paint go transparent. One attribute, and no frame of an un-bordered box.

Scope: rectangles, and ellipses where the element is `.circle`. No hachure fill, no curves, no per-node bespoke shapes. A `tiles` container is never sketched (its children are the items it counts); its rows are CSS's, not the frame's, so v1 leaves them alone. Native popups — `<select>`'s dropdown, a date picker — belong to the browser and are never covered.

Cost: one observer and one path string per sketched node. A thousand-card wall would be a thousand observers, so the gate is a measured number (Order, step 5); if it fails, the answer is "the container is sketched, not the rows", not a second mechanism.

wasm facts, recorded so they are not rediscovered: `rand 0.8` reaches `getrandom 0.2`, which refuses `wasm32-unknown-unknown` without its `js` feature, so the crate needs a `cfg(target_arch = "wasm32")` dependency line. Size, measured on this machine with the same toolchain, release loom built at the commit before the skin versus after: 2,679,684 → 2,812,265 bytes (+132.6 KB, +4.9%); the dev loom 9,524,795 → 10,262,783 (+738 KB, +7.7%). That is the once-per-dependency cost of `palette`/`euclid`/`svgtypes`/`svg_path_ops`, not a per-node one — and it is the number that was owed before anything was attached.

## 5. No settings surface, but the page may own its half

An option nobody can see is an option nobody can audit, and the answer is still not a panel. The far side sets the options when it draws the page, so the audit is the frame itself: the `set`/`patch` on the option slot travels in the same stream as the `create` that built the page, replayable like every other frame, greppable in the console.

So the reference host ships no configuration surface, `#main` grows no attribute for one, and the shell is the two columns: no bar, no switch of the framework's. What a page may do is own its own half: a control whose `sink` names a `path` into the option slot is a normal node making a normal local write (§2) — the page was always allowed to decide its own values (ADR 0031 §1), and an option is one of them. A page that wants the switch draws it where its own layout has room for it. The walkthrough puts it in the graph's bottom-right corner — the `panel` with `place: anchor` in `examples/yaml/00.main.yaml`, floating over space nothing else uses (ADR 0030) — because `#main` grows no bar for it and the shell stays two columns.

What the earlier version of this section refused — a frame writing options — is refused for a different reason now, and the reason is worth keeping: the write is **local only**. The far side's object is what the page falls back to, so a control cannot reach the producer's half, only say "this reader chose otherwise". That is a preference, not a privilege.

## Rejected

- **`vars`, a second page-value plane.** That is `inject` under a new name: a store whose far side could overwrite the page's own assignment — precisely the power §1 removes. ADR 0031 closed the door conceptually; this ADR closes it in code.
- **A namespace of their own** (`config`, `vars`). The first was this ADR's original answer and is retired: it needed an op, an API, a type per option and a mirror per option to say what a slot and a `path` already said. The second is `inject` under a new name (below).
- **A `<RoughFrame>` wrapper component.** The CSS is structural: `--tile-fields` is a track list written from the field count (tiles.rs:413 → core.css:552,579), and `.tiles > *` styles the items (core.css:708). An element between a container and its items *is* a track or an item. A drawing that needs no space must not occupy one.
- **`border-image` from a generated data-URI SVG.** Cheapest by far, and two costs end it: colours are baked into the document (no `currentColor`, so a dark page gets light-mode ink), and `border-image` ignores `border-radius`, which silently voids the frame's own shape.
- **An `feTurbulence`/`feDisplacementMap` filter on a pseudo-element.** Real displacement in ten lines of CSS, and it is pixel noise, not a stroke: it blurs the edge instead of drawing a second, wavering line, and it cannot do hachure. The tell of a sketch is the stroke.
- **Shipped SVG assets per widget type.** A static asset cannot follow the box's size, and a hand-drawn *asset* is a picture of a border, not a border.
- **A handwriting font.** A CJK face is megabytes for text that is mostly CJK. Not in this skin, and not soon.

## Order

1. Delete `inject` — variant, op, arm, guard, tests, example, documentation rows, ADR 0011 status. (Done in this change.)
2. The option slot: `config` in the mount options, `config_get`/`config_members`, a sink `path` writing into the local plane, the per-member fallback in `hooks::value_of`, and the bool read a checkbox needs. (Revised: the `config` op, `Ctx.config`, `set_config` and the per-option signals are gone.)
3. The `data-<member>` mirror on the document root, the skin block in `core.css`, and the bar that owns `sketch` from the page's side. Live check: the bar's checkbox flips `html[data-sketch]`, the drawn borders appear and go, and the page returns to exactly its pre-skin state.
4. `rough_border` in ui_core, `roughr` behind a wasm target dependency, the size probe — the measured delta goes into this ADR before anything is attached.
5. Attach at the five widgets. Gates: `normal` renders no observer and no extra node; `sketch` covers `examples/yaml` (tabs, form, login, table, chart, forcegraph); frames per second with a 200-row list.
